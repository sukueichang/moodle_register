# 排程需求（實體課）

## 兩套邏輯

### 1. 管理員「編輯場次」

- 可自訂開始時間（半小時刻度）。
- 「接續當日上一場結束時間」僅作建議起點；可改為 14:30、15:00 等。
- 結束時間 = 所選開始 + 課程連動預設課時（含午休、跨日、每日時數上限）。
- 同日同教室允許多場，僅限時段不重疊。

### 2. 專屬開班預排月曆（業務 + 系統管理員審核）

適用情境（皆須可拖曳）：

1. 業務初次預排（2/3 月曆）
2. 業務再次編輯已存預排
3. 系統管理員審核月曆（`review=1`）

規則：

- 拖曳或初次產生時，**開始時間 = 該教室當日上一場的結束時間**（精準相接，例如 A 14:00 結束 → B 14:00 開始）。
- **結束時間**由伺服器依課程預設課時重算（`calculate_session_times(..., respect_start=true)`）。
- 與「編輯場次」不同：預排**不可**在接續點之後再任意延後半小時；要調整緩衝請用編輯場次。
- **教室未開放**占用時段計入當日「實體課每日時數上限」；當日已滿則不接續排課，改下一個工作日 09:30。
- 課程區間**不得落在週六／週日**；若會跨到假日，整段改排至下一個工作日。

## 升級與 Pending 申請

- 不修改既有 `calendar_plan_json`，直至使用者再次儲存預排。
- 儲存時伺服器會依開始時間正規化結束時間（實體課）。
